# 最低价初始化、dry-run 与环境镜像

## 实例与环境选择

仅在 [首次运行或环境实质变化](../SKILL.md#先确定运行模式) 时初始化；已有兼容且已验收镜像则直接复用。

查询授权团队/集群的实时套餐，先筛选代码、GPU、CUDA/架构、显存和内存要求，再选最低价可用项。只有代码可在 CPU 完整验收时才选更便宜 CPU 实例；CPU 导入不能代替 GPU 路径验证。使用最低必要卡数和覆盖安装、dry-run、镜像保存的有界时长，不提前按正式实验购高配；无最低价适用资源时报告候选及价格，不静默升级。

按主流程完成认证、查重、密钥与 [挂载](storage-datasets.md)，同步当前源码及依赖清单后配置环境。

## 镜像与挂载的边界

| 保存内容 | 位置与要求 |
|---|---|
| 解释器、框架、系统库、CUDA 用户态依赖、启动配置 | 镜像实际保存的非挂载文件系统，例如确认未被挂载覆盖的 `/opt/venv` |
| 源码、数据、日志、结果和环境清单 | 持久化挂载，后续恢复挂载并同步当前代码 |
| 环境变量、设备可见性和资源规格 | 任务配置或启动脚本明确设置，不能假定交互式 `export` 被镜像捕获 |

检查平台快照范围及解释器、链接目标、动态库，避免依赖未声明路径。挂载中的虚拟环境不假定随镜像保存；需要完整镜像时在保存范围内重建并验证，不能直接搬动环境后假定绝对路径仍有效。

## dry-run 验收

从真实项目入口执行最小、有限、正常退出的运行。原生 dry-run 只在确认覆盖关键链路时使用；否则缩小样本、步数和评估规模，不虚构参数。

通过条件包括关键导入、所需 GPU 真实计算、真实数据读取、初始化与必要的前向/更新/业务步骤；项目需要时还验证日志、评估和检查点实际恢复后的前向或动作，不能只看文件存在。真实退出码为 `0`、达到目标进度、关键数值有限且无未处理异常。

在本次工作区保留命令、代码版本或工作区标识、依赖清单与产物。失败则修复重跑，通过前不标记为可复用环境或转入正式长实验。

## 保存环境镜像

1. 安装和 dry-run 完成、文件落盘后，确认保存的是刚验收的环境，移除不需保留的临时文件，排除私钥、登录凭据和令牌。
2. 用平台当前的保存/制作镜像功能选择准确源实例、仓库、权限和新版本标签，不覆盖正被实验使用的版本。[API 方法、字段和状态](web-api.md#保存环境镜像接口) 以当前前端为准，不虚构 `bita save/commit` 或假定容器拥有宿主 Docker 权限。
3. 等待保存完成且镜像可用于创建任务，核对完整引用、ID、标签及可取得的 digest，关联环境清单和 dry-run 结果。请求被接受不是完成。
4. 确认镜像与持久化产物可用后再按本次安排停止初始化实例，避免提前中断制作。保存失败保留恢复条件并报告；不把“镜像就绪”说成“已在新实例验证”。

镜像与运行记录放当前项目或任务产物，不写回技能。

镜像制作期间 SSH 可能暂时不可用；先结合准确镜像和源任务状态判断，不仅凭一次 banner 超时就重装 VPN、重复保存或重建付费实例。

## 后续实验复用

选择保存成功的兼容镜像，在 YAML 中核对实际引用并尽量记录 digest；恢复挂载、数据版本和当前源码，再按实验需求选择资源。

该镜像首次用于后续实例时验证拉取、启动、依赖、GPU 和数据，最小 dry-run 通过后扩大运行。在已安排的下一个实例验收，不默认另开并行付费实例。兼容时不重复安装依赖；依赖、解释器、CUDA/架构实质变化才生成新镜像版本，源码变化则同步验证。
