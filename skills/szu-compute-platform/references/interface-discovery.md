# 接口与客户端行为的定位

仅在字段含义不明、部署变化或现有调用失败时读取。先用 [只读查询助手](web-api.md#只读查询助手) 获取当前结构；以下是已验证过的定位方法，不是固定版本的承诺。

## 从当前前端确认行为

1. 仅通过 HTTP 客户端下载控制台当前 HTML 和配置，按实际 `script/module` 引用下载入口 JS，再跟进相关模块的 import；离线读源码，不打开、渲染或执行页面，不用浏览器开发者工具或抓取浏览器会话。不要长期复用旧构建文件名。
2. 使用 `rg` 搜索关键字。压缩文件常只有一行，找到位置后只截取有限上下文，避免输出整份脚本。优先沿具体功能查调用链：命令行传输、创建任务、任务详情、SSH 说明、存为镜像。
3. 同时检查调用函数与 HTTP 封装。`post(path, {data: payload})` 中的 `data` 可能是封装配置，需确认最终在线请求体，不能直接额外套一层 `data`。
4. 先用已有权限的只读接口核对结构，再在本次已授权的范围内执行写操作。前端 toast、HTTP 200 或 CLI 退出码不代替平台最终状态。

| 待确认内容 | 有效证据与用法 |
|---|---|
| bita 的 `-u/-p` | 查当前生成登录命令的逻辑；已核实使用 `name/pubPassword`。请求体字段叫 `password` 仍不能证明它要求 CAS 密码 |
| CLI 历史协议 | 仅参考已有脱敏协议证据和静态源码；当前流程直接用 HTTP，不执行 CLI 探测，不用真实账号试错 |
| 导出 YAML 的时长 | 对照创建表单的小时到分钟换算、API `debugDuration` 和已有限时任务导出；不按字段名猜单位 |
| SSH 的实际地址 | 优先完整连接说明。`debug-url.sshUrl` 可能只给内部地址；结合当前集群 `sshProxyPath` 与前端构造逻辑取得用户、任务主机、SOCKS5 入口，不能直接把裸 IP 当公网 SSH 地址 |
| 任务实际使用的镜像 | 已核实详情位于 `jobTaskList[].jobTaskImage.path`；用 YAML `imagePath` 创建时 `imageId` 可以为空，不能因此判断镜像没拉取 |
| 任务实际规格 | 已核实详情位于 `jobTaskList[].jobTaskPowerConf`；不要把界面汇总文字或空的同名顶层字段当作资源详情 |
| 保存镜像 | 查保存表单的请求函数、`uploadType/sceneList` 和镜像状态映射，按 [镜像接口](web-api.md#保存环境镜像接口) 核对 |

字段缺失时先检查响应层级和客户端转换，不逐一猜接口路径。凭据、含 token 的 URL、私有仓库密码及原始认证响应不进入发现记录；只保留方法、路径、字段含义和脱敏示例。

## 把每次尝试变成下一步判断

- 认证失败：先检查凭据角色、账号、租户与 endpoint，按 [HTTP 认证分支](bita.md#web-api-认证流程) 处理；不通过浏览器复制登录命令，不用一次 500 给接口或密码定性。
- 网络或 SSH 失败：先分清 DNS、TCP/SOCKS5、SSH banner 和公钥认证阶段，再转 [代理](proxy-bypass.md) 或 [连接](remote-runtime.md#ssh-连接)；只有 banner 超时不构成重建依据。
- 任务或镜像提交无明确 ID：先完整查询并核对本次唯一名称、集群、团队、创建时间与配置，得到准确 ID 后继续，不重复提交。
- 同一列表前后变化：区分本次动作与其他任务的并发变化，保留无关任务，不能为恢复旧快照去停止或重建它们。

项目记录保存“观察到的证据、已做动作、结果、下一步和准确资源 ID”。技能只保存已验证的通用分支；实验参数、依赖特定版本、价格、账号与资源 ID 留在项目记录中。
