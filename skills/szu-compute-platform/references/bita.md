# Web API 认证与 bita 配置兼容

本技能只通过 Web API 操作平台；不执行 `bita login/apply/upload/download`，不通过浏览器取得凭据。保留本文用于解释历史客户端协议、复用已有本机认证和排查登录问题。

## 认证

校园 VPN、平台会话和 SSH 是不同的认证层。SecureLink 在线不等于平台认证可用；SSH 公钥也不能替代平台会话 token。

### 先分清三种凭据

| 凭据 | 用途 |
|---|---|
| 学校 CAS 密码及二次认证 | 学校统一认证；通过正常认证回调取得平台会话 |
| 平台 CLI 登录凭据 `pubPassword` | 历史客户端的 `login -p` 输入；可用于已确认的登录交换接口 |
| 平台会话 token | 平台 API 请求头 `token`；已核实的 bita 配置将其 Base64 编码存入 `auth` |

已核实的静态前端使用 `name`、`pubPassword`、`tenantInfo.name` 生成 CLI 命令。`pubPassword` 不等于会话 token，也不能从会话 token 经 Base64 编解码得到；尚未确认其具备 OAuth refresh token 的刷新、过期与轮换语义。

## Web API 认证流程

1. **复用已有会话。** 已有本机 bita 配置时，按 [API 认证检查](web-api.md#使用边界与认证) 读取、在内存中解码并发只读请求验证；不回显 token。不读取浏览器 cookie、存储或会话数据库。认证有效即继续，不为获取 `pubPassword` 再次登录。
2. **已有 CLI 凭据时。** 在本机受限输入通道取得平台账号及 `pubPassword`，按当前部署已确认的登录交换接口发送 HTTPS 请求；不把学校密码代入。本地协议探测曾定位 `POST /gateway/ram/api/v1/tenant/user/login`，请求体为 `name/password/tenantName/productId`，其中 `password` 承载 CLI 凭据，历史值为 `tenantName=szdx`、`productId=heros`。这只是已观察到的客户端协议，尚未以真实 CLI 凭据验证完整登录成功；调用前确认部署、响应结构和业务码，不将其写成固定保证。
3. **没有有效会话或 CLI 凭据时。** 通过 HTTP 客户端访问官方认证入口，按当前表单、脚本和接口完成 CAS/二次认证；保持同一 cookie 会话、隐藏字段和回调状态，所需请求构造或加密逻辑从当前静态资源核实，不硬编码旧盐值、票据或过期字段。只向已确认的学校/平台 HTTPS 域名发送相应凭据；逐跳核对重定向，不把平台 token 或密码转发到其他域名。
4. **二次认证。** 通过官方已确认的验证码发送与校验接口操作；用户在本机终端的受限输入中填写验证码，不发到聊天。不得打开浏览器或提供需要浏览器填写的本地页面。若只提供图形交互、扫码或尚未确认无浏览器的二次认证方式，停止认证分支并报告所缺能力，不绕过二次认证。
5. **验证与保存。** 从正常登录回调取得平台会话 token 后，以只读接口同时核对 HTTP 状态、业务码及账号身份。按本次需要保存到本机受限凭据位置；兼容现有 bita 配置时合并写入 `.auths[endpoint].auth = Base64(token)`，保留其他 endpoint，Windows 使用用户专属 ACL，POSIX 使用 `600`。写入配置不代表执行过 CLI 登录，也不证明 token 可用作 `login -p`。

接口字段无法确认时先做 [静态接口定位](interface-discovery.md#从当前前端确认行为)；认证失败不反复提交账号试错。会话过期回到此流程，不假定 `pubPassword` 可自动刷新会话。

## 通过 API 获取 pubPassword

仅在本次确需 CLI 兼容凭据且已有相应授权时，通过已认证的账号资料或 CLI 命令生成接口取值；先从当前静态 JS 定位实际接口、请求和响应层级，不假定某个 profile 接口必然返回 `pubPassword`，也不猜测隐藏接口。

取到后只在内存或本机受限凭据位置使用，不输出完整命令或原始认证响应。[只读查询助手](web-api.md#只读查询助手) 会脱敏该字段，因此其输出不能用来导出 `pubPassword`。若当前权限或接口不提供该值，报告限制；不得让用户改用网页复制。现有平台会话可用时，直接完成 Web API 任务，无需额外获取此字段。

## 历史 CLI 提交的排障证据

曾遇到 `bita apply` 退出码为 0、标准输出却没有 ID。接手此类未决任务时，通过 API 完整分页查询当前集群，按唯一名称、团队、创建时间及规格匹配准确 ID；空输出不等于没有提交。多个匹配或配置不符先调查，不盲目重建。后续创建改用已确认的 API，按 [主流程](../SKILL.md) 核价、查重和验收。

Base64 只是编码。CLI 凭据、会话 token、cookie 和二次认证状态始终留在本机受限位置，不进入 Git、镜像或实验产物。
