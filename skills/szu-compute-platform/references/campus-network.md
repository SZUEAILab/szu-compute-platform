# 校园网环境与 SecureLink 接入

## 判断接入状态

结合当前网络配置、校园接入客户端状态、平台域名的真实解析、到目标 IP 的路由和入口连通性判断。Wi-Fi 名称、私网 IP、进程、`tun` 接口或公网学校主页可访问，都不足以单独证明校园内网可用。

| 判断结果 | 下一步 |
|---|---|
| 校园网直连且平台可达 | 复用直连 |
| SecureLink 在线且平台经其路由可达 | 复用 VPN，不重复安装或登录 |
| 校外网络，尚未建立校园接入 | 报告网络前置条件；只使用已确认的无 GUI 接入方式 |
| 证据不足或连接失败 | 说明待确认项，排查 DNS、代理与路由，不仅凭超时判定用户在校外 |

测试平台当前域名的 DNS、目标路由、控制台 HTTPS 与 SSH 代理端口，具体地址和端口取自当前连接说明。无需通过断开有效连接来判断用户是否身处校园。

CAS 登录的校内外分支见 [认证流程](bita.md#web-api-认证流程)：用户提供的部署经验是校内账号密码、校外另加企业微信二次认证，最终以 CAS 实际挑战为准。校园 VPN 连通不等于免除二次认证，也不等于已取得平台或 CLI token。

## 校外接入步骤

1. **复用已有接入。** 通过本机进程、接口、路由和连通性诊断已有 SecureLink，不启动浏览器或操作 VPN 图形界面。学校企业标识的历史值为小写 `szu`，学校 CAS 认证与算力平台会话独立。
2. **缺少接入时。** 若有当前官方明确支持的无 GUI 接入接口或命令，核对其文档、权限和认证后使用；不猜测 VPN 私有接口。尚无已确认方案时报告“校园接入未就绪”，将其列为外部网络前置条件，继续不依赖内网的准备工作；不让用户为本技能打开认证网页，也不声称纯 HTTP 请求能替代 VPN 隧道。
3. **检查冲突。** 核对其他 VPN、TUN、DNS 接管和代理的影响；按 [proxy-bypass.md](proxy-bypass.md) 配置深大域名例外。不自动卸载其他 VPN 或中断已有连接。
4. **验收并继续。** 验证平台域名真实解析、目标路由、HTTPS 只读请求和 SSH 代理入口。全部可用后继续原任务，不能只以客户端“在线”判定接入完成。

## 失败分流

- 接入认证未完成：检查已有无 GUI 方式的明确失败原因；缺少该方式时报告网络阻塞，不回退浏览器。
- 已在线但解析异常：检查校园 DNS、代理远端 DNS 与 Fake-IP。
- 解析正确但目标不可达：检查目标路由、VPN 分流、访问权限和服务状态。
- 需要用户补足外部网络前置条件时明确当前步骤，同时继续独立的只读诊断；校园接入不自动授权创建算力实例。
