# 校园网环境与 SecureLink 接入

## 判断接入状态

结合当前网络配置、校园接入客户端状态、平台域名的真实解析、到目标 IP 的路由和入口连通性判断。Wi-Fi 名称、私网 IP、进程、`tun` 接口或公网学校主页可访问，都不足以单独证明校园内网可用。

| 判断结果 | 下一步 |
|---|---|
| 校园网直连且平台可达 | 复用直连 |
| SecureLink 在线且平台经其路由可达 | 复用 VPN，不重复安装或登录 |
| 校外网络，尚未建立校园接入 | 提醒用户，并按下述步骤辅助配置 |
| 证据不足或连接失败 | 说明待确认项，排查 DNS、代理与路由，不仅凭超时判定用户在校外 |

测试平台当前域名的 DNS、目标路由、控制台 HTTPS 与 SSH 代理端口，具体地址和端口取自当前连接说明。无需通过断开有效连接来判断用户是否身处校园。

## 校外接入步骤

1. **提醒与准备。** 告知“当前尚未接入校园内网，需要先通过学校 SecureLink 接入”。检查本机是否已有可用 SecureLink，确定操作系统与架构；已安装时直接复用。
2. **安装与启动。** 缺少客户端时，从 SecureLink 官方下载入口 `https://www.wangsu.com/app/securelink/` 获取适配安装包，辅助下载、安装和启动。Windows 使用适配安装程序，macOS 使用适配芯片的安装包；移动端可从正规应用商店获取。其他系统先确认官方适配版本和安装包说明，不套用其他系统的安装步骤。入口不可用或缺少适配版本时报告具体阻塞。
3. **配置学校身份。** 企业标识填写小写 `szu`。选择“第三方登录”中的“CAS”；移动端可显示为“统一身份认证”。在打开的学校统一身份认证页面登录。此流程独立于算力平台的 `bita login`。
4. **完成交互。** 用户在认证页面自行输入账号密码并完成二次认证；浏览器询问是否打开 SecureLink 时选择打开。对安装提权、网络/VPN 权限、用户条款等交互，说明提示和下一步，由用户完成。不要让用户把密码、验证码或认证票据发到聊天。
5. **检查冲突。** 核对其他 VPN、TUN、DNS 接管和代理的影响；按 [proxy-bypass.md](proxy-bypass.md) 配置深大域名例外。定位冲突后处理，不自动卸载其他 VPN 或中断用户已有连接。
6. **验收并继续。** 确认客户端在线，再验证平台域名真实解析、目标路由和 HTTPS/SSH 代理入口。全部可用后继续原平台任务；不能只以客户端“在线”判定接入完成。

## 失败分流

- 认证未完成：引导用户完成统一认证、二次认证及浏览器回调。
- 已在线但解析异常：检查校园 DNS、代理远端 DNS、Fake-IP 与浏览器安全 DNS。
- 解析正确但目标不可达：检查目标路由、VPN 分流、访问权限和服务状态。
- 需要用户交互时明确当前步骤，同时继续可独立完成的只读诊断；配置校园接入不自动授权创建算力实例。
